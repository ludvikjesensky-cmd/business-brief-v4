# Fast Editorial — Reconstruction Evidence & Guardrails

**Status:** GREENFIELD REFERENCE  
**Purpose:** separate what is historically supported from what is reconstructed, and protect the new process from over-formalization.

---

## 1. Evidence classes

Use three labels when reconstructing or changing the process.

### DOCUMENTED

Explicitly supported by the original experiment conversation or recorded artifacts.

### STRONG RECONSTRUCTION

Very likely to reflect the actual method, but not directly preserved as an exact historical specification.

### UNCERTAIN / UNPROVEN

Must not be presented as historical fact.

---

## 2. Documented elements

The reconstruction supports with high confidence that:

- complete editions of three publications were processed;
- publication order could vary;
- every edition received an independent Issue Map;
- Issue Maps were frozen before Cross-Paper;
- later editions did not retroactively redefine earlier frozen maps;
- articles were not supposed to collapse prematurely into broad Topics;
- priorities CORE / CANDIDATE / LOW were used;
- Deep Read candidates were identified;
- image-based FT could be read visually without full-issue OCR;
- article / continuation / teaser / advertisement distinctions mattered;
- Cross-Paper created Daily Topics and provenance links;
- provenance roles primary / supporting / contrasting / background were used;
- strong single-source stories could survive selection;
- Selective Deep Read preceded Editorial Review;
- documented Day 2 Deep Read all 12 INCLUDE Topics;
- Deep Read changed interpretation without necessarily changing selection;
- eight named editorial passes existed;
- each pass produced an Editorial Note;
- Dramaturgy could combine multiple Daily Topics into one final reader-facing unit;
- Brief hierarchy and variable item length mattered;
- Detail review checked Brief vs deeper value;
- Verification caught errors introduced during writing;
- Language & Style used read-aloud review;
- Editor-in-Chief could pass without edits;
- final gates included Coverage, Hierarchy, Curiosity, Trust, Product fit and 90-second test;
- verified did not automatically mean published;
- temporal continuity was useful but not a mandatory formal pass.

## 3. Strong reconstruction

The following are useful but should not be called exact historical specifications:

- precise reader persona;
- exact field names in YAML structures;
- exact responsibilities of every pass beyond the observed behavior;
- correction protocol for frozen maps;
- exact source contribution semantics;
- exact minimal artifact filenames;
- exact cross-day continuity handoff;
- exact internal state model;
- exact final Brief section structure.

---

## 4. Uncertain / unproven

Do not claim historical certainty for:

- exact original SQL schema;
- exact mandatory fields;
- exact Master Brief section names and ordering;
- exact target length;
- fixed number of main stories;
- numeric editorial scoring;
- exact 90-second testing protocol;
- formal Temporal pass;
- separate agents or Chats for each editorial role;
- assumption that every Detail was fully produced;
- assumption that verified meant published.

---

## 5. Anti-overformalization rules

Do not formalize the following merely because they can be modeled:

| Area | Keep primarily editorial | Failure mode if over-formalized |
|---|---|---|
| Importance | human/model judgment over the article | easy-to-score stories win |
| Story angle | live synthesis | formulaic sameness |
| Article grouping | mechanism-based judgment | keyword taxonomy takes over |
| Length | value-based | hierarchy flattens |
| Number of leads | day-dependent | weak stories get promoted |
| Curiosity | content-derived | clickbait |
| Return to source | available throughout | verification becomes procedural |
| Internal comparison | live context | audit bloat |
| Eight passes | perspectives of one process | context loss across agents |
| Review edits | only when justified | good text gets damaged |
| Memory | supportive | yesterday dominates today |
| Workflow state | minimal | process starts governing content |

---

## 6. Core reconstruction principle

The strongest recoverable lesson is:

> Quality came from one Chat that first read the individual editions honestly, then found the real daily stories, then returned to source, and finally judged one common text repeatedly from different editorial perspectives.

The purpose of formalization is to protect:
- independent issue reading;
- frozen provenance;
- return to source;
- meaningful interpretation changes;
- final quality judgment.

Everything else should remain as light as possible.

---

## 7. Change discipline during greenfield reconstruction

Before adding a new rule, field, artifact, role or state, ask:

1. Was this documented in the working experiment?
2. If not, is it necessary to preserve editorial quality?
3. Does it help return to source or preserve a consequential decision?
4. Could the same value remain in live Chat context?
5. Does the new formalism risk becoming a substitute for editorial judgment?

If the answer to 2 or 3 is weak, do not add it yet.
